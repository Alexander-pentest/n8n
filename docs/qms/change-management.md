# Verfahren: Änderungsmanagement

## Zweck

Das Änderungsmanagement stellt sicher, dass Änderungen geplant, risikobasiert bewertet, freigegeben, umgesetzt und nachverfolgt werden.

## Änderungsarten

| Änderungsart | Beispiele |
| --- | --- |
| Prozessänderung | Neuer Ablauf, geänderte Verantwortlichkeiten, geänderte Kontrollen. |
| Produkt- oder Serviceänderung | Funktionale Änderung, Architekturänderung, geänderte Servicebedingungen. |
| Lieferantenänderung | Neuer Dienstleister, geänderte SLA, geänderte kritische Abhängigkeit. |
| Dokumentenänderung | Neue oder überarbeitete QMS-Dokumente, Vorlagen oder Arbeitsanweisungen. |

## Prozessschritte

1. **Antrag:** Änderung mit Begründung, Umfang und gewünschtem Wirksamkeitsdatum erfassen.
2. **Bewertung:** Auswirkungen auf Qualität, Kunden, Sicherheit, Datenschutz, Compliance, Schulung und Risiken prüfen.
3. **Freigabe:** Verantwortliche Rollen und gegebenenfalls Geschäftsführung genehmigen die Änderung.
4. **Umsetzung:** Aktivitäten, Kommunikation, Dokumentenupdates und Schulungen durchführen.
5. **Verifikation:** Prüfen, ob Änderung wie geplant umgesetzt wurde.
6. **Wirksamkeitsprüfung:** Nach definierter Zeit kontrollieren, ob gewünschte Wirkung erreicht wurde.

## Pflichtprüfungen

Jede relevante Änderung muss auf Auswirkungen für [Risikomanagement](./risk-management.md), [Dokumentenlenkung](./document-control.md), [Schulung](./training.md) und offene [CAPAs](./capa.md) geprüft werden.
